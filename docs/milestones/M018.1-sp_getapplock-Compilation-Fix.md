# M018.1 – `sp_getapplock` Compilation Fix

The procedure now creates the lock resource in a local
`nvarchar(255)` variable before invoking `sys.sp_getapplock`.

```sql
SET @LockResource = CONCAT(
    N'ConfiguredProduct:',
    @FamilyCode,
    N':',
    @ConfigurationSignature
);

EXEC @LockResult = sys.sp_getapplock
    @Resource = @LockResource,
    @LockMode = 'Exclusive',
    @LockOwner = 'Transaction',
    @LockTimeout = 15000;
```

The migration remains idempotent, so it is safe to rerun after the
earlier partial execution.
