## 0. Context — authoritative-workbook re-base

Mid-D140, engineering delivered a NEW authoritative workbook
`workbooks/Dean/PumpConfiguration_Logic_0.1.xlsm` (PCL v0.1). Per direction it
**supersedes ALL prior Dean constraint/config/numbering sources** (the old
`PumpConfiguration_Logic.xlsm`, `Dean Data Sheet Rev 2.xlsm`, and
`Dean Data Sheet Rev 2` numbering) for series, impellers, wet ends, power frame,
baseplate, flush, and motor-frame numbering — **except seal**, which remains
OMITTED-not-discarded pending engineering's seal code (A1).

D140 therefore did two things: (a) re-loaded the Dean identifier numbering + the
resolver onto v0.1, and (b) built the D140 Excel-oracle regression parity check
against v0.1. The old workbook is no longer referenced by any live Dean loader,
resolver, or oracle.

**Key structural fact:** PCL v0.1 is a *numbering/constraint authority*, not an
interactive Smart-Number configurator. It has **no `Data Sheet` input sheet and
no `Smart Number` Part-Number output**. Each PN segment has its own numbering
sheet enumerating `(option ComboString -> Alphanumeric Code)` rows (built by the
`Module1`/`Module2` VBA). The D140 oracle reflects this: it reads the segment
codes LIVE from those numbering sheets and proves the SQL/API reproduces them.

## 5. Known gaps (disclosed, NOT glossed)

- **A1 — Seal (OPEN, seal-only).** Seal code is authored only in the external
  `Seal Numbering.accdb`; engineering is still working the seal configuration
  code. Seal is **OMITTED from the Dean PN but NOT discarded** (segment slot
  retained). Additionally, **519 seal codependency tuples were skipped** in D110
  because the Codependencies sheet's long seal descriptions do not reconcile with
  the Pump Constraints short seal names (needs a crosswalk). The one 4-leg quad in
  the workbook is the seal quad and is therefore not enforced.
- **A2 — External "Standard Confs" DB (OPEN).** For ~36/42 sampled models the
  D110 STD seed lands on a wet_end/power_frame combo the workbook numbering never
  enumerated (the fully-specified standard row lives in an external Access DB we
  don't have), so those two segments resolve to `?` for those models. This is the
  ONLY place `?` is permitted; the identifier audit fails on a `?` anywhere else.
- **F1 — Cooling Plan Numbering EMPTY** in v0.1 → cooling segment is a retained
  placeholder `00`.
- **F2 — Barrier Plan Numbering header-only (0 data rows)** in v0.1 → barrier
  segment is a retained placeholder `0`.
- **F3 — Motor main Alphanumeric Code inert (`000`)** in v0.1 → the live motor
  differentiation is the Frame-Size sub-table (loaded as MOTOR_FRAME); the main
  motor code segment is a retained placeholder `0000`.
- **No Testing / Documentation / Additional-Options numbering sheet** in v0.1 →
  those segments are retained placeholders (`00`/`0000`/`00`).

All unbuilt/placeholder segments are emitted as fixed zero-padded values (never
`?`), so the Dean PN never errors and every slot is preserved for a clean
drop-in once engineering delivers the missing tables.
